## 3. 总目标与完成标准

### 3.1 产品目标

同一套通用系统服务：

1. **GPT-2**；
2. **YOCO-MoE-A0.4B**；
3. **YOCO-3B**，作为 held-out 验收模型。

输入包括完整 SM/PM authority、真实 topology/group/layout 信息和明确 caller contracts；输出应为完整 kernel-checked public 等价证明，或者定位明确、分类正确的失败。

最终系统形态应是：

```text
配置与原始图/源码证据
  → 统一 topology / ordered group / layout / ownership authority
  → 共享 certificate / segment / relation DAG
  → 多目标投影与完整 whole-model/public theorem
  → exact-source kernel、合同、信任与发布验收
```

已有算子与布局的新组合，不应依赖手写模型、Goal、层号、节点号或 tensor-ID 专用证明。新算子或新布局可以扩展公共库，但必须形成可复用规则，而不是给特定模型补一条隐含假设。[S1；S2]

### 3.2 关闭总目标的必要门禁

- 同一 canonical IR、faithful `evalOp`、typed ownership/relation、certificate 和 composition/kernel 路径。
- 覆盖原始完整 public-target ancestry，保留错误或无法表达的目标作为 finding，不缩小分母。
- 一次调用期间零源码修改、零模型专用 proof body；完整 public statement 不被加强前提或削弱结论。
- 第二次独立调用输出确定性一致；每模型对 op、ownership/relation、side condition、graph edge、certificate 做负控。
- exact generated bytes、全部 imports/objects、axiom footprint 与原 theorem contract 同时通过；不是“renderer 返回了文本”。
- 分开记录生成、规划、输出、cold/warm kernel、缓存来源、峰值 RSS 和最慢模块；不能用旧缓存续跑时间冒充 cold baseline。
- unseen architecture/held-out 验收不能用同模型重复层替代。

在三模型总门禁完成之前，不发布项目、不推送或合并 `main`。正确报告一个局部失败是工具能力，但不是“三模型完整证明”的完成证据。[S1:78–102；S2:19–76]

### 4.1 导入、authority 与输入

- `Verdict/nnscaler_backend/`：从实际 nnScaler 图恢复执行节点、lineage、writer 和 rank source；安装环境中的 nnScaler 是运行依赖。
- `trainverify/runtime_source_authority.py`：tensor 身份包含 `(world, runtime_rank, microbatch, source_tid, version)`；writer 还区分实际 call/op/origin。单独 raw TID 不足以唯一识别值。
- `trainverify/parallel_topology.py` 与 `trainverify/bridge_emitter/parallel_authority.py`：把配置、ordered groups、rank-local 坐标与模型图绑定；不从 shape/rank 数量猜 ownership。

### 4.2 数学语义层

- `trainverify/denote/Denote.lean` 定义 Tensor、Store、NodeDecl/GraphDecl 和执行语义；其中 `Scalar := ℝ`，不是 IEEE 浮点 CUDA 模拟器。
- `DenoteDistributedFaithful.lean`、`ZigzagCollective.lean`、`GroupScopedEval.lean`、`AllToAllSourceFaithful.lean`、`SourceScopedEval.lean` 承接跨 rank、显式 group、source-faithful collective 与 scoped `Option Store` 执行。

**数学等价、真实执行存在性、Torch/CUDA 实现 refinement 是不同层级。** GPU 容差测试、版本 pin、保存 capture 或 Lean Real 等式，均不能单独证明全部浮点实现正确。[S1:72–76；S10]

## 5. 相对远程基线，修改改进了什么

`9cfbfc78` 已经包含 Lean 语义、YOCO/GPT 证明基础、typed rule/planner 和通用 proof-compiler 纵向切片。因此以下成果是**继承后的扩展和强化**，不能把既有基础全部计成本轮从零创造。

### 5.1 来源与值语义更忠实

解决 raw TID、rank、microbatch、version 混淆，以及仅按形状/局部 identity 推断通信等价的问题。现在按完整 fullref、writer call、readpoint、ordered peers 和真实参数来源接续；源节点的值、shape 和全执行后缀不写条件一起保留。

改进意义：证明更接近实际 source graph，能将 upstream 反例、翻译错误和缺引理分开，而不是为通过下游证明掩盖上游问题。

### 5.2 并行配置与 ownership 成为显式输入

配置经 pinned source topology helpers 推导，绑定 ordered groups、rank scope、坐标、布局角色与模型 authority。逻辑 replica、通信 group、DP chunk、partial reduction、zigzag permutation 不再混作“几个同形 tensor”。缺信息与明确空信息区别处理，合法但 backend 不支持的 subgroup 显式拒绝。

改进意义：为通用并行配置建立可验证入口；但配置元数据推导仍不是 captured graph 来自该配置的证明，也不是 Lean topology theorem。

### 5.3 从逐 Goal 重复证明走向共享 DAG 与 prefix

模型 authority、共享 certificate/relation DAG 和多 target projections 减少重复组织；runtime prefix 用同一 Store 链的 read/frame/continuation 保存已证事实。共享不能偷偷增加 union 初值假设，也不能把图内计算值搬成外部 InitGoal。

改进意义：后续扩模型、扩层或扩目标可以复用公共组件与精确前驱对象；当前仍需把两条组织路径收口到一致的完整系统验收。

### 5.4 forward 与 backward 共享真实 saved-primal 来源

反向 reader/consumer 已按原始 mirror、ordered operands、reducer ownership/scaling 接线。反向所需 QKV/score 的前向值，采用同一 source frontier，而不是再维护一套重复前向实现。

最新已接到 score matmul 和 score AA(1,3)。已有 backward readers、局部 dX/dW/shape 结果不等于 saved activations 和整个反向链已闭合。

### 5.5 在固定预算内保留完整证明

prefix identifier v3/v4/v5 与 **read-source v3** 是两套不同版本轴。最新 read-source v3 只在 validated-seed 模式显式启用固定通用词表，保持历史 v1/v2 默认解释不变。

actual1 的完整拒绝包由 2,507,958 降到 2,498,512 bytes，净省 9,446 bytes；全部 notation/support 开销计入，130 support 与声明顺序不变。不是抬上限、删查询、删事实或移动文件逃避计费。

### 5.6 验收与 claim 不再混在一个返回码里

区分 source/规划/生成、kernel、完整合同、public 和 refinement。fresh-only publication、完整 membership/import/source/receipt 检查、macro-aware 查询和完整 Expr 对比防止“代码生成了就算证明完了”。

两类真实工具问题已经正确处置：正常多行 axiom 输出补足受限 parser；大入口出现 linter warnings 时不放宽 parser，而用独立全 target import observer 检查同一对象。原失败、日志和对象均保留，恢复结果单独记账。

### 5.7 源码与证据生命周期可维护

前向/反向源码收敛到唯一开发树；历史未提交研究、捕获、已接受对象和原 HEAD 有恢复材料。原工作树兼容别名已退役，必须通过显式 layout 解析历史逻辑路径。维护脚本纳入 Git，机器路径与数据留在外部配置。

改进意义：接手人不需要猜某个旧目录是不是第二套 canonical，也不会误把 `.lake/build` 或 ignored kernel 证据当垃圾。但“源码已合并”不等于外部 evidence 已打包进 Git。

## 8. 当前缺口及优先级
